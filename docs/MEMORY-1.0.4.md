# PortPilot 1.0.4 内存与响应验证

## 改动

- WPF LiveFiltering 原先为每个视图的每行同时监听多个字段，包括没有查询的情况。现在只为已提交搜索和筛选所需的字段建立绑定；无条件时关闭实时筛选监听，实时排序仍保留。
- `InspectorRow.Update` 按字段通知变化。CPU/内存采样不再发送“所有属性变化”，避免重复读取端点文本、身份信息、重新筛选与布局。
- 原先每个端口行都会对同一 PID 的全部端点执行监听端口去重、排序和拼接。现在每个 PID 每轮只计算一次，并在后台完成。
- Network 使用有限视口的虚拟化回收列表，仅实例化可见区域附近的条目；仍保留完整端点数据，滚动可访问全部内容。
- 关闭详情清空展示数据并取消请求。每个请求负责释放自己的 linked CancellationTokenSource，避免注册一直保留至程序退出；修复 Inspect 同时由属性变化和命令重复发起请求的问题。
- 详情缓存使用 LRU 淘汰、32 项上限、估算 4 MiB 保留预算及 5 分钟过期时间。已退出进程清理、PID + StartTime 身份校验继续生效；超出预算的单项仍正常显示但不缓存。

## 相同流程对比

2026-09-21，Windows 11 x64，.NET 8.0.425，20 个逻辑处理器。分别使用独立便携目录运行原逻辑和优化逻辑；各额外创建 400 个真实回环 TCP 监听端点。本机总端点约 2400–2950 个，包含其他程序活动带来的变化。

五个阶段各 40 秒：Dashboard → Ports → Network → 每轮反复查看同一进程详情 8 次 → 关闭详情并移除测试端点。每轮扫描后等待 2 秒，没有主动 GC、清空工作集或修改系统内存设置。

| 阶段 | 工作集均值，前 → 后（MiB） | 私有提交均值，前 → 后（MiB） | 每轮分配均值，前 → 后（MiB） | 扫描及应用均值，前 → 后（ms） |
| --- | --- | --- | --- | --- |
| Dashboard | 384.2 → 204.5 | 319.0 → 139.3 | 17.87 → 2.94 | 128.7 → 39.5 |
| Ports | 437.2 → 238.6 | 366.1 → 166.2 | 17.65 → 3.38 | 137.1 → 59.9 |
| Network | 454.4 → 254.0 | 379.6 → 177.9 | 18.74 → 3.08 | 155.5 → 83.1 |
| 详情反复开关 | 482.5 → 285.5 | 406.0 → 206.9 | 18.59 → 11.09 | 168.1 → 100.4 |
| 关闭详情后 | 470.6 → 262.9 | 393.1 → 182.8 | 8.46 → 2.60 | 110.8 → 72.1 |

- 全流程工作集峰值：488.59 → 292.34 MiB，约降低 40%。
- 托管内存峰值：158.11 → 25.24 MiB。末次样本：118.04 → 15.84 MiB。
- 输入优先级 Dispatcher 探针 P95：3.13 → 2.96 ms；最大值 460.04 → 363.66 ms。探针测量排队响应，不能当作键入到屏幕显示的完整延迟。
- 归一化 CPU 均值：0.54% → 0.42%。

原始采样：[优化前](performance/1.0.4-before.json)、[优化后](performance/1.0.4-after.json)。对比在版本号更新前采集，两个文件中的程序集版本均为 1.0.3.0；before 为旧逻辑加测量入口，after 为本次优化逻辑。

工作集包含驻留代码、运行时及共享页面；PrivateMiB 是私有提交内存；ManagedMiB 是未强制 GC 的托管分配估计。这些数值与任务管理器各列不能直接混用。内存会随端点数、访问的页面、缓存与系统压力变化，不能据此承诺所有机器都低于某个固定 MB 值。

## 最终 EXE 持续运行验证

v1.0.4 发布 EXE 按五阶段各 120 秒运行，实际采样覆盖 605.34 秒：292 轮扫描、449 次详情请求，额外 400 个测试端点。与上传制品 SHA256 一致。原始记录：[10 分钟采样](performance/1.0.4-soak.json)。

- 全程工作集峰值 292.46 MiB，托管内存峰值 26.55 MiB。
- 最后一分钟已关闭详情并移除测试端点，30 次样本工作集在 270.82–272.23 MiB，私有提交 192.65–194.10 MiB；托管内存随 GC 在 13.88–25.80 MiB 间波动；句柄数 647–650。
- 最后一分钟工作集首尾为 270.84 → 272.23 MiB，没有观察到此前反复操作造成的大幅累积；测试期间其他本机进程/端点仍在变化。这是有限时长验证，不代表无限运行时间或所有负载下的固定上限。
- Dispatcher 探针 P95 3.10 ms，最大值 281.72 ms；归一化 CPU 均值 0.39%。

## 功能验证

- 构建 0 警告、0 错误；79 项自动化测试全部通过。
- 新增缓存容量、字节预算、LRU、过期、PID 复用、退出清理、并发边界及细粒度属性通知测试。
- 实际 WPF UI 回归：远程端口/IP/连接状态变化仍更新筛选结果；清空搜索后去除无用字段监听；CPU 实时排序正常。
- Network 打开 120 个真实监听端点和 UDP/已建立连接；实际容器少于 64，末尾端点可达，反复切换、刷新和删除端点正确。
- 深浅主题图标、搜索提交、中文长文本和搜索框裁切回归通过。

## 复现

```powershell
./build.ps1
./measure.ps1                      # 五阶段，各 40 秒，额外 400 个端点
./measure.ps1 -PhaseSeconds 120    # 约 10 分钟
```

脚本复制发布 EXE 至 `.verification/perf-*` 独立目录，报告位于其 `data/cache/performance.json`。仅统计测量进程，不结束其他程序，也不使用原有便携 data。每次只运行一组测量，避免相互干扰。
